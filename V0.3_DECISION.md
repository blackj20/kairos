# V0.3 — Couche de décision

## Statut

**Validée le 28 juillet 2026.**

Cette version ajoute une couche entre `Comprendre` et les composants de sortie :

```text
Comprendre
    ↓
Évaluer
    ↓
ChoisirRoute
    ↓
VerifierDecision
    ├── autorisation
    └── Demande
            ↓
      question en attente
            ↓
      réponse utilisateur
            ↓
        Expérience
```

## Responsabilités

### Évaluer

- calcule un score décisionnel ;
- détecte les champs manquants ;
- détecte plusieurs actions ;
- estime les routes possibles ;
- ne produit aucun effet de bord.

### ChoisirRoute

- sélectionne la route ayant le meilleur score ;
- refuse les routes inconnues ;
- ne produit aucun effet de bord.

### VerifierDecision

- contrôle la cohérence entre le type et la route ;
- bloque une exécution incomplète, ambiguë ou insuffisante ;
- vérifie le rôle de l'acteur ;
- appelle `Demande` quand une information manque ;
- ne crée lui-même aucune donnée.

### Demande

- formule une question ciblée ;
- crée une question en attente ;
- crée un événement d'apprentissage quand le score est inférieur ou égal à
  50 % ;
- marque comme prioritaire un score inférieur ou égal à 30 %.

### Expérience

- relie une réponse à sa question ;
- analyse la réponse ;
- résout provisoirement le champ demandé ;
- conserve le statut `recorded_not_confirmed` ;
- ne modifie jamais la mémoire confirmée.

## Seuils

```text
85–100 % → route autorisée
51–84 %  → confirmation
31–50 %  → clarification et étude
0–30 %   → explication prioritaire
```

Un champ obligatoire absent ou plusieurs actions bloquent l'exécution,
indépendamment du score global.

## Persistance

Par défaut, `Kernel()` utilise un stockage en mémoire vive afin que les tests et
les analyses isolées ne modifient pas les fichiers.

```python
Kernel(persister_decisions=True)
```

active uniquement :

- `memory/pending_questions.json` ;
- `memory/experiences.json` ;
- `memory/learning_events.json`.

Les fichiers `confirmed.json`, `hypotheses.json` et `history.json` restent
intacts.

## Limites volontaires

- `Repondre` reste un adaptateur provisoire ;
- aucune expérience n'est transformée en connaissance ;
- `Réfléchir`, `GrowUp`, `Relier` avancé, `Tester` et `SECAU` ne sont pas
  implémentés ;
- la confirmation est enregistrée, mais pas encore interprétée comme une
  autorisation d'exécuter lors d'un second passage ;
- une session interactive suppose que la prochaine entrée répond à la question
  en attente.
